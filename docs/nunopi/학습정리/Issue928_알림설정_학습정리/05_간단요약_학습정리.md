# Issue 928 학습 정리 — 간단 요약

## 이 이슈를 한 문장으로 요약하면
> 흩어진 알림 설정(에이전트 완료·터미널 벨·포커스 억제)을 하나의 설정 스토어로 모아 벨 버튼과 설정 페이지를 양방향으로 묶고, 테스트 버튼이 결과를 토스트로 노출하게 한 작업.

## 먼저 잡고 가야 할 핵심 개념
- **단일 설정 스토어 + 구독 동기**: 모든 설정을 `mustard:settings` 하나에 담고, `subscribeSettings`로 값 변경을 여러 UI에 방송. 한쪽을 바꾸면 다른 쪽이 즉시 반영(양방향).
- **state vs ref**: state는 화면 다시 그리기용, ref(`notifyOnRef`)는 폴링 콜백 클로저 안에서 최신값을 읽기용. 클로저가 옛 state를 붙잡는 문제를 ref로 우회.
- **포커스 억제 게이트**: `suppressWhileFocused !== false && win.isFocused()`. 명시적 `false`일 때만 억제 해제, 그 외엔 기존 동작(창 보면 억제) 유지.
- **`ok:true` ≠ 화면 표시**: IPC 호출 성공과 OS 실제 알림 표시는 다른 층. adhoc 서명이면 macOS가 조용히 드롭.

## 설계 포인트
- 낡은 `localStorage` 키(`nunopi:notifyAgentDone`)를 직접 쓰던 걸 스토어로 이관 + 1회 멱등 마이그레이션(새 값 없을 때만 옮김).
- 벨 알림은 `suppressWhileFocused: false`로 보냄(현재 창 이벤트라 억제 무의미). 완료 알림은 설정값을 실어 보냄.
- 테스트 버튼은 기존 공용 `useToast`를 재사용(새로 안 만듦) — notify 반환값만 노출.

## 구현 흐름 압축
1. `settings.ts`에 `NOTIF_DEFAULTS`/`NKEYS` 정의.
2. `WorkspaceTabs`: 벨 토글을 `setSetting`으로, `subscribeSettings`로 설정 페이지와 동기, 옛 키 마이그레이션, 완료 알림에 `suppressWhileFocused` 실어 보냄.
3. `main.cjs` notify 처리기: `suppressWhileFocused !== false && isFocused()`면 스킵.
4. `Terminal.tsx`: `onBell` → 설정 켜져 있으면 notify, cleanup에서 `bellDisp.dispose()`.
5. `SettingsDrawer`: 알림 섹션 3토글 + 테스트 버튼(`sendTestNotif`가 결과 토스트), i18n 3키.

## 여기서 많이 헷갈리는 포인트
- **`suppressWhileFocused !== false` vs `if (suppressWhileFocused)`**: 후자로 하면 `undefined`(값 미전달) 시 억제가 꺼져 기존 동작이 깨진다. 반드시 `!== false`.
- **subscribeSettings 반환 릭 오해**: `useEffect(() => subscribeSettings(...), [])`는 화살표 암묵 반환으로 unsubscribe가 cleanup 등록됨 → 릭 아님. 리뷰 false positive.
- **테스트 알림 안 뜸 ≠ 버그**: adhoc 서명 탓. 코드는 `ok:true`. 정식 서명 dmg에서 표시.
