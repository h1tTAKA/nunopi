# Issue 928 학습 정리 — 질문과 답

작업 중 내가(유저) 실제로 물어본 것들 + 답. 복습용.

## Q1. "테스트 알림 보내기 이거 잘 작동 안하는거 같은데?"
**A.** 눌러도 화면에 아무 반응이 없어서 그렇게 느낀 것. 버튼이 알림을 쏘라고 시키기만 하고 결과를 안 보여줬기 때문. 그래서 버튼에 **결과 토스트**를 붙였다 — 누르면 "전송됨"/"실패 (사유)"가 화면에 뜨게. 고친 뒤 확인해보니 토스트는 "전송됨"으로 뜨는데 macOS 알림은 안 떴다(아래 Q2로 이어짐).

## Q2. "테스트알림 전송됨이라고 토스트 뜨긴하는데 mac알림은 안뜸"
**A.** 코드는 정상이다. "전송됨"(`ok:true`)은 우리가 `Notification.show()`를 제대로 호출했다는 뜻. 안 뜨는 이유는 **dev 빌드가 adhoc(임시) 서명**이라서다. macOS는 정식 서명 안 된 앱의 알림을 조용히 버린다(알림센터 등록조차 안 함). `codesign -dv`로 `Signature=adhoc` 확인됨. **Developer ID 정식 서명 + notarize한 배포용 dmg**에서는 뜬다. 지금 dev로는 "실제 표시"까지는 검증 불가, "호출 성공(ok)"까지만 확인 가능.

## Q3. (A/B 선택) 이 상태로 어떻게 진행할까?
**A.** 두 안 제시 → 유저가 **A안** 선택:
- **A**: 코드 유지, 서명 시 표시. 학습정리에 "adhoc 서명 한계" 기록. ← 선택됨.
- B: 지금 임시로 시스템 설정 > 알림에 앱 등록 시도(adhoc라 안 뜰 가능성 높음).

핵심 교훈: **IPC 호출 성공(ok:true)과 OS의 실제 알림 표시는 다른 층이다.** 그 사이를 코드서명이 가른다. 우리가 코드로 보장할 수 있는 건 호출 성공까지고, 표시는 서명/notarize 문제다.
