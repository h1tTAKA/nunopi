# Issue 928 학습 정리 — 터미널 벨 알림 + 포커스 억제 게이트

## 핵심 요약
> ①터미널이 "삑"(벨) 울리면 데스크톱 알림을 띄우는 기능과, ②창을 보고 있을 땐 알림을 참는 "포커스 억제"를 설정으로 켜고 끌 수 있게 배선한 작업.

## 유저 관점에서 보면?
- 터미널 벨: 긴 명령이 끝나 삑 소리 날 때, 다른 창 보고 있어도 알림으로 알 수 있음(설정 켜야 동작, 기본 꺼짐).
- 포커스 억제: 기본은 "창 보고 있으면 알림 안 뜸"(방해 안 됨). 근데 테스트하거나 원하면 이 억제를 꺼서 창을 봐도 알림이 뜨게 할 수 있음.

---

## 1. 큰 그림 (구조 + 이름 먼저)

### 비유
알림에는 **문지기(게이트)** 가 있다. 알림이 나가려 할 때 문지기가 묻는다: "지금 사장님(사용자)이 이 창을 보고 있나?" 보고 있으면 "그럼 굳이 알릴 필요 없지" 하고 막는다(억제). 근데 사장님이 "테스트니까 보고 있어도 띄워"라고 미리 쪽지(`suppressWhileFocused: false`)를 주면 문지기는 그냥 통과시킨다.

### 부품과 역할
| 부품 | 역할 |
|---|---|
| `term.onBell` (xterm) | 터미널이 벨(`\x07`) 받으면 부르는 콜백 등록. 끄는 객체 반환 |
| `window.nunopiDesktop.notify()` | 렌더러(화면)에서 메인(일렉트론)에게 "알림 띄워줘" 요청 |
| `ipcMain.handle("notify")` | 메인 쪽 알림 처리기. 문지기 역할 |
| `win.isFocused()` | 창이 지금 포커스(맨 앞·활성) 상태인지 |

### 새로 지은 이름들
| 이름 | 정체 |
|---|---|
| `bellDisp` | `onBell` 구독을 나중에 끄기 위한 손잡이(dispose 가능 객체) |
| `NKEYS.terminalBell` | "터미널 벨 알림" 설정 열쇠 |
| `NKEYS.suppressWhileFocused` | "포커스 중 억제" 설정 열쇠 |

## 2. 동작 ↔ 코드 (1대1)

**1) 터미널 벨 → 알림** — `Terminal.tsx:102`:
```ts
bellDisp = term.onBell(() => {
  if (getSetting<boolean>(NKEYS.terminalBell, false))
    window.nunopiDesktop?.notify?.({
      title: "🔔 Terminal",
      body: cwd.split(/[\\/]/).filter(Boolean).pop() || "",
      suppressWhileFocused: false,
    });
});
```
🔍 **뜯어보기**
- `term.onBell(() => {...})` = 벨 울릴 때마다 이 함수 실행. 반환값을 `bellDisp`에 담아 나중에 끔.
- `getSetting<boolean>(NKEYS.terminalBell, false)` = 설정 읽기, 없으면 `false`(기본 꺼짐). 켜져 있을 때만 알림.
- `window.nunopiDesktop?.notify?.(...)` — `?.`는 "없으면 그냥 넘어가"(옵셔널 체이닝). 웹 환경엔 `nunopiDesktop`이 없어서 이 가드가 필요.
- `cwd.split(/[\\/]/).filter(Boolean).pop()` = 작업 경로를 슬래시로 쪼개고(`/a/b/c`→`["","a","b","c"]`), 빈 것 버리고(`filter(Boolean)`), 마지막(`pop()`) = 폴더 이름만. 알림 본문에 "어느 폴더서 울렸는지" 표시.
- `suppressWhileFocused: false` = 벨 알림은 **창 보고 있어도 뜨게** (삑 소리는 지금 이 창 이벤트라 억제하면 의미 없음).

**2) 청소(cleanup)** — `Terminal.tsx:189`:
```ts
return () => { /* ... */ bellDisp?.dispose(); /* ... */ };
```
🔍 **뜯어보기**
- `useEffect`의 반환 함수 = 컴포넌트 나갈 때 뒷정리.
- `bellDisp?.dispose()` = 벨 구독 해제(있을 때만). 안 하면 터미널 여러 번 열고 닫을 때 옛 콜백이 계속 쌓임(릭).

**3) 완료 알림 시 억제 설정 전달** — `WorkspaceTabs.tsx:144`:
```ts
void window.nunopiDesktop?.notify?.({
  title, body: name,
  suppressWhileFocused: getSetting<boolean>(NKEYS.suppressWhileFocused, NOTIF_DEFAULTS.suppressWhileFocused),
});
```
🔍 **뜯어보기**
- `void` = 이 Promise 결과 안 기다리고 버림("불 지르고 잊기"). 알림은 성공 여부 안 따져도 됨.
- `suppressWhileFocused`에 **설정값을 실어보냄** → 문지기(메인)가 이 값 보고 억제 여부 결정.

**4) 문지기(메인) 판정** — `main.cjs:494`:
```js
ipcMain.handle("notify", (_e, payload) => {
  const { title, body, suppressWhileFocused } = payload ?? {};
  if (!Notification.isSupported()) return { ok: false, reason: "unsupported" };
  if (suppressWhileFocused !== false && win && win.isFocused()) return { ok: false, reason: "focused" };
  const n = new Notification({ title: title || "nunopi", body: body || "", icon: notifyIconPath() });
  n.show();
  return { ok: true };
});
```
🔍 **뜯어보기**
- `const { title, body, suppressWhileFocused } = payload ?? {}` = 객체에서 필요한 값만 꺼내기(구조분해). `?? {}`는 payload가 없으면 빈 객체로(터짐 방지).
- `suppressWhileFocused !== false` = **핵심.** 값이 명시적으로 `false`일 때만 억제 안 함. `undefined`(안 보냄)나 `true`면 억제 켜진 것으로 봄 → **기존 동작 유지가 기본.**
- `&& win.isFocused()` = 그리고 창이 실제 포커스 중일 때 → `{ ok:false, reason:"focused" }`로 막음.
- 통과하면 `new Notification(...).show()` = OS 알림 띄우고 `{ ok:true }`.

### 여기서 짚을 포인트
- **왜 `!== false`로 비교?** 기본을 "억제 켜짐"으로 두고, 오직 명시적 `false`만 예외로 하려고. `if (suppressWhileFocused)`로 하면 `undefined`일 때 억제가 꺼져버려 기존 동작이 깨짐.
- **벨은 왜 `suppressWhileFocused: false`?** 벨은 지금 이 창의 터미널 이벤트라, 창 보고 있어도 알려야 의미 있음.
