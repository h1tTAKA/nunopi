# Issue 928 학습 정리 — 알림 설정 스토어 이관 + 양방향 동기

## 핵심 요약
> "에이전트 완료 알림 켜짐/꺼짐" 상태를 탭 구석 벨 버튼과 설정 페이지 **두 곳에서 똑같이 보고 똑같이 바꿀 수 있게** 하나의 저장소로 합친 작업.

## 유저 관점에서 보면?
- 전에는: 탭 위쪽 벨 버튼으로만 알림을 껐다 켰다 할 수 있었음. 그 값은 `localStorage`의 `nunopi:notifyAgentDone`이라는 낡은 열쇠(키)에 따로 저장됨.
- 이제는: 설정 페이지 "알림" 섹션에도 같은 토글이 생겼고, **한쪽을 바꾸면 다른 쪽도 즉시 따라 움직임.** 벨을 끄면 설정 페이지 토글도 꺼지고, 설정에서 켜면 벨도 켜짐.

---

## 1. 큰 그림 (구조 + 이름 먼저)

### 비유
설정값을 **회사 공용 화이트보드** 하나로 통일했다고 보면 된다. 예전엔 벨 버튼이 자기 수첩(옛 localStorage 키)에 몰래 적어놨다. 이제는 모두가 같은 화이트보드(`mustard:settings`)를 보고, 누가 고치면 화이트보드 옆에 붙은 종(subscribeSettings)이 울려서 "값 바뀌었다!" 하고 알려준다. 그 종소리를 들은 사람은 자기 화면을 다시 그린다.

### 부품과 역할
| 부품 | 역할 |
|---|---|
| `mustard:settings` (localStorage JSON) | 모든 설정을 담는 **단일 화이트보드** |
| `getSetting(key, fallback)` | 화이트보드에서 값 하나 읽기 |
| `setSetting(key, value)` | 화이트보드에 값 하나 쓰기 + 구독자에게 알림 |
| `subscribeSettings(listener)` | "값 바뀌면 이 함수 불러줘" 등록. **끄는 함수(unsubscribe)를 돌려줌** |
| `WorkspaceTabs`의 벨 버튼 | 알림 on/off 토글하는 UI |
| `SettingsDrawer` 알림 섹션 | 같은 값을 토글하는 설정 페이지 UI |

### 새로 지은 이름들
| 이름 | 정체 |
|---|---|
| `NOTIF_DEFAULTS` | 알림 설정 3개의 기본값 뭉치 `{ agentDone: true, suppressWhileFocused: true, terminalBell: false }` |
| `NKEYS` | 알림 설정들의 화이트보드 열쇠 이름 모음(`agentDone` 등) |
| `notifyOn` (state) | 벨 켜짐 여부. 화면 다시 그리기용 |
| `notifyOnRef` (ref) | 같은 값을 폴링 콜백 안에서 최신으로 읽기 위한 "주머니" |

## 2. 동작 ↔ 코드 (1대1)

**1) 알림 3종 기본값·열쇠 정의** — `packages/core/src/settings.ts:47`:
```ts
export const NOTIF_DEFAULTS = { agentDone: true, suppressWhileFocused: true, terminalBell: false };
export const NKEYS = { agentDone: "notif.agentDone", /* ... */ };
```
🔍 **뜯어보기**
- `export const` = 다른 파일서 갖다 쓸 수 있게 내보내는 상수(변하지 않는 값).
- 객체 `{ agentDone: true, ... }` = 이름표 붙은 값 묶음. `agentDone`이라는 이름에 `true`가 붙음.
- `agentDone`=에이전트 다 하면 알림, `suppressWhileFocused`=창 볼 때 알림 참기, `terminalBell`=터미널 삑 소리 시 알림.

**2) 벨 토글 → 스토어에 쓰기** — `WorkspaceTabs.tsx:116`:
```ts
const toggleNotify = () => {
  const next = !notifyOnRef.current;      // ← 지금 값 뒤집기(켜짐↔꺼짐)
  notifyOnRef.current = next; setNotifyOn(next); // ← 주머니랑 화면상태 둘 다 갱신
  setSetting(NKEYS.agentDone, next);      // ← 공용 화이트보드에 기록(설정 페이지와 공유)
};
```
🔍 **뜯어보기**
- `!x` = 참/거짓 뒤집기. `!true`는 `false`.
- `notifyOnRef.current` = ref(주머니)에 든 현재 값. state와 달리 바꿔도 화면이 다시 안 그려짐 → 폴링 루프 안에서 최신값 읽을 때 씀.
- state(`setNotifyOn`)와 ref 둘 다 두는 이유: **state는 화면 그리기용, ref는 콜백 안에서 최신값 읽기용.** 폴링 콜백은 처음 만들어질 때 값을 "사진 찍어" 들고 있어서, ref가 없으면 옛날 값을 보게 된다.

**3) 설정 페이지서 바뀌면 벨도 따라가기(양방향 동기)** — `WorkspaceTabs.tsx:122`:
```ts
useEffect(() => subscribeSettings(() => {
  const v = getSetting<boolean>(NKEYS.agentDone, NOTIF_DEFAULTS.agentDone);
  notifyOnRef.current = v; setNotifyOn(v);
}), []);
```
🔍 **뜯어보기**
- `useEffect(() => ..., [])` = 컴포넌트 뜰 때 딱 한 번 실행(`[]`=빈 의존성).
- 화살표 함수 본문이 `subscribeSettings(...)` **하나뿐** → 그 결과(끄는 함수)를 **암묵적으로 반환**한다. `useEffect`는 반환된 함수를 "나갈 때 뒷정리(cleanup)"로 쓴다. 즉 컴포넌트가 사라질 때 자동으로 구독 해제됨 → **메모리 릭 없음.**
- `subscribeSettings`는 `settings.ts:91`에서 `() => { listeners.delete(listener); }`(구독 취소)를 돌려주므로 이 패턴이 정상.
- ⚠️ 리뷰에서 "반환값 미캡처 릭"으로 지적됐으나 **오판(false positive)** — 화살표 암묵 반환으로 이미 cleanup 등록돼 있음.

**4) 옛 키 1회 마이그레이션** — `WorkspaceTabs.tsx:183`:
```ts
try {
  const old = localStorage.getItem("nunopi:notifyAgentDone");
  if (old !== null && getSetting(NKEYS.agentDone, null) === null) {
    setSetting(NKEYS.agentDone, old !== "0");        // ← 옛 값을 새 화이트보드로 옮김
    localStorage.removeItem("nunopi:notifyAgentDone"); // ← 옛 열쇠 제거
  }
} catch { /* ignore */ }
```
🔍 **뜯어보기**
- `old !== null` = 옛 키가 실제로 있었을 때만.
- `getSetting(NKEYS.agentDone, null) === null` = 새 화이트보드에 **아직 값이 없을 때만** → 두 번 옮기는 것 방지(멱등, 한 번만 실행).
- `old !== "0"` = 옛 저장 형식이 문자열 "0"/"1"이라 "0이 아니면 켜짐"으로 변환.
- `try { } catch { }` = localStorage 접근이 막혀도(시크릿 모드 등) 앱이 안 죽게 감쌈.

### 여기서 짚을 포인트
- **왜 state랑 ref 둘 다?** 화면 갱신(state) ≠ 콜백 안 최신값 읽기(ref). 폴링 `.then` 클로저가 옛 state를 붙잡는 문제를 ref로 우회.
- **왜 마이그레이션에 "새 값 없을 때만" 조건?** 사용자가 이미 새 설정을 만졌으면 옛 값으로 덮으면 안 됨. 한 번만 옮기고 끝.
